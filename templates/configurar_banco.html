⚙️ Provisionamento do Banco

Ações de configuração inicial. Salve a conexão acima primeiro (isso já cria as tabelas de controle no schema de destino), depois rode: banco local → FDW → schema temp.

1. Banco de dados local

Cria o banco "{{ db_config.database }}" no host configurado acima (via conexão à base de manutenção postgres), caso ainda não exista.

2. Foreign Data Wrapper (origem)

Cria a extensão postgres_fdw, o servidor remoto, o mapeamento de usuário e importa as tabelas do schema remoto para o schema local abaixo. Pode ser rodado de novo para atualizar credenciais ou importar tabelas novas.

Prefixo usado nas migrações, ex: {{ fdw_config.schema_local or 'fdw_externo' }}.v_paciente.
O teste confere a origem direto com os dados acima (senha em branco usa a salva) e faz uma consulta pelo FDW já criado no banco local — que é o caminho usado nas importações.

3. Schema de staging (temp)

Cria o schema {{ temp_schema_name }}, usado para copiar cada lote de IDs antes de gravar no schema de destino configurado acima.

4. Tabelas de controle

controle_migracao, controle_migracao_lotes, auto_importacao_tabelas, auto_importacao_ciclos e auto_importacao_ciclo_registros já são criadas/verificadas automaticamente no schema de destino sempre que você salva a conexão acima (seção 1) ou troca a conexão ativa na lista de conexões salvas.

As funções SQL da migração (processar_lote, verificar_progresso, preparar_colunas_migracao, atualizar_lotes_migracao, finalizar_migracao...) também são criadas/atualizadas automaticamente no schema de destino {{ db_config.schema_destino or 'public' }} — junto com as tabelas, na subida do sistema e pelo botão abaixo.
Revisar e Corrigir confere as tabelas de controle de importação: cria o que faltar, recria com id BIGINT as tabelas de detalhe antigas (id INTEGER, que estouram em 2,1 bilhões) e apaga os logs de importação mais antigos — ficam só os últimos {{ logs_importacao_mantidos }} ciclos/execuções de cada tabela (essa limpeza também roda sozinha a cada novo log).
